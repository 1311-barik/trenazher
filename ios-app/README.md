# Тренажёр для Андрея — iOS/iPadOS-приложение

> **Заморожено 2026-09-19.** Основная версия — веб-приложение `../web-app/` (https://trenazher-135-181-197-13.nip.io): без платного Apple Developer Program и без доступа к iPhone Андрея нативную версию не установить удалённо. Код ниже рабочий и остаётся на случай, если решение поменяется.

Нативное приложение на SwiftUI (iOS 14+ / iPadOS 14+) по ТЗ v3 (`../docs/tz-v3.docx`).
Статус на 2026-09-19: **MVP написан целиком, собирается и проходит тесты. На iPhone/iPad ещё не запускался** — на Mac нет Xcode. Платный Apple Developer не используем: данные на каждом устройстве свои, установка — из Xcode с бесплатным Apple ID.

## Как устроено

**Контент.** Приложение само читает таблицу «Дрон тренировка» (Google Sheets API) и три папки (Drive API) по read-only API-ключу, без OAuth и без своего сервера. Из них собирается манифест: упражнения, готовые тренировки, привязанные файлы и замечания. Женя правит таблицу — Андрей получает изменения при следующей синхронизации (при запуске, раз в 30 минут или кнопкой). Сборщик манифеста — чистая функция (`ManifestBuilder`), тот же код работает в утилите `content-report`.

**Сопоставление файлов** — только однозначное: явное имя файла или ссылка в ячейке, либо имя файла, совпадающее с названием упражнения («Пресс. Мертвый жук.JPG» ↔ «Мертвый жук»). Похожие названия идут подсказками в отчёт, но автоматически не привязываются.

**Кэш и офлайн.** Манифест — JSON-файл, медиа — файлы с версией в имени. Новая версия фото не затирает старую, пока не скачается. Обрыв связи → при следующем запуске докачиваются только недостающие файлы. Фото качаются всегда, видео — заранее по Wi-Fi (настройка) или по тапу.

**Данные Андрея.** Избранное и история — Core Data, настройки — UserDefaults. Всё хранится на устройстве и попадает в его резервную копию iCloud. Синхронизация iPhone ↔ iPad (CloudKit + iCloud Key-Value) написана, но **выключена**: решение от 2026-09-19 — без платного Apple Developer Program. Включается конфигурацией, без правки кода (см. ниже). Идущая тренировка сохраняется на диск после каждого действия и восстанавливается после закрытия приложения.

**Совместимость с iOS 14.** Без `NavigationStack`, `.task`, `AsyncImage`, async-методов URLSession и прочего новее iOS 14. Пакет собирается и под macOS 11 — компилятор сам ловит API новее этой планки.

## Решения, отличающиеся от ТЗ v3 или уточняющие его

| Пункт ТЗ | Решение | Почему |
|---|---|---|
| 5 частей тела (попа, руки, спина, ноги, пресс) | Части тела берутся из таблицы — сейчас их 8 | В таблице уже 8 разделов, и называются они иначе («Живот», «Плечи», «Грудь», «Смесь мышц») |
| Кэш — Core Data или GRDB | JSON-файл + папка медиа | 40 упражнений, лишняя зависимость не нужна |
| Скрипт сборки манифеста | Манифест собирает само приложение | ТЗ допускает оба варианта; так не нужен ни сервер, ни ручной запуск скрипта |
| Конвенция имён файлов — согласовать | Имя файла или ссылка в ячейке + точное совпадение названий | Сейчас в ячейках «есть», а имена файлов не совпадают с названиями упражнений |
| Готовые тренировки — формат не задан | Лист «Тренировки» в той же таблице | Женя работает в привычной таблице |
| Подходы | Необязательная колонка «Подходы», находится по заголовку | Как в ТЗ 4.6 |
| Таймер: вручную или автоматически | Запускается после «Подход выполнен» и отдельной кнопкой «Отдых»; по умолчанию 60 с; после последнего подхода не запускается | ТЗ оставляет на усмотрение разработчика |
| Синхронизация iPhone ↔ iPad через iCloud (6.2, критерий приёмки 4) | **Отложена**: данные на каждом устройстве свои | Решение 2026-09-19: без платного Apple Developer Program. Код готов, включается конфигом |
| Напоминания | Расписание на устройстве; с iCloud появится переключатель «на этом устройстве» | Чтобы при синхронизации iPhone и iPad не звенели одновременно |
| Навигация по карточкам | Кроме «Следующее» есть «‹ Предыдущее» и «Вернуться к последнему» из «Ещё хочешь?» | Стандарт юзабилити: у каждого действия есть обратное |
| — | «Повторить тренировку» из истории, «Начать с этого упражнения» из избранного | Короткий путь к основной ценности |

## Что нужно, чтобы запустить

1. **Xcode** из App Store (сейчас на Mac только Command Line Tools).
2. **API-ключ Google.** Google Cloud Console → новый проект → включить *Google Sheets API* и *Google Drive API* → Credentials → API key → ограничить по iOS bundle ID `com.barsky.trenazher` и этим двум API.
3. **Доступ к папке.** Женя: «Андрей тренировка» → «Поделиться» → «Все, у кого есть ссылка» → Читатель. Сейчас доступ только у владелицы и приглашённых — по ключу приложение папку не увидит.
4. **Secrets.xcconfig.** Скопировать шаблон и вписать ключ:

```bash
cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig
```

5. Открыть проект и запустить в симуляторе (⌘R):

```bash
open Trenazher.xcodeproj
```

6. **Установка на iPhone или iPad Андрея с бесплатным Apple ID** (платный аккаунт не используем):
   - Xcode → Settings → Accounts → добавить Apple ID; в проекте Signing & Capabilities → Team: *Personal Team*;
   - подключить устройство кабелем, выбрать его вверху Xcode, ⌘R; на устройстве: Настройки → Основные → VPN и управление устройством → доверять разработчику;
   - **подпись действует 7 дней**: раз в неделю подключать устройство к этому Mac и снова нажимать ⌘R. Данные (история, избранное, скачанное) при переустановке сохраняются, пропадают только при удалении приложения;
   - TestFlight и App Store без платного аккаунта недоступны.

**Если позже появится Apple Developer Program ($99/год):** в Secrets.xcconfig вписать `DEVELOPMENT_TEAM`, раскомментировать `CLOUDKIT_CONTAINER_ID` и `APP_ENTITLEMENTS`, в Xcode включить iCloud-контейнер. Синхронизация iPhone ↔ iPad, TestFlight и подпись на год заработают без правки кода.

## Что проверено и что нет

Проверено:
- компиляция всего пакета (логика и экраны) без ошибок и предупреждений;
- 32 теста: разбор реальной таблицы, сопоставление файлов, версии, кэш, сессия тренировки (все прямые и обратные переходы), восстановление после перезапуска, избранное и история с отменой, настройки локально и между устройствами, таймер, синхронизация контента с обрывом связи и офлайн;
- вёрстка всех экранов — рендер на Mac (`docs/previews/`).

Не проверено (нужны Xcode и устройство):
- сборка под iOS: ветки `#if os(iOS)` с UIKit (вибрация, звук, «не гасить экран», настройки iOS) компилятором не проверялись;
- реальные запросы к Google (нет ключа, нет доступа по ссылке);
- локальные уведомления, видеоплеер, работа в фоне (CloudKit и push выключены вместе с платным аккаунтом);
- вид на iPhone/iPad: на Mac шрифты мельче, а системные контролы выглядят по-маковски.
