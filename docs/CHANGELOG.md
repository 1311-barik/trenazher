## 2026-09-20

### Визуальный слой: золото вместо красного
Подбор визуальной системы — скилл `ui-ux-pro-max`, разбор его рекомендаций и решения по каждой — `design-system/trenazher/MASTER.md`. Палитру скилла (оранжевый) и шрифты с Google Fonts не берём: синяя база задана ТЗ, а офлайн-приложение не должно ходить за шрифтами.

- **Красный `#e3222d` убран** — по просьбе владельца, акцент теперь золотой, как на его сайтах: заливка `#f0b429` с тёмно-синим текстом (9.8:1), текст и иконки `#ffd166`. Красный остался только за необратимым и сбоями (`--danger`).
- **Кольца фокуса не было вообще** — с клавиатуры и при VoiceOver не было видно, где находишься. Добавлено золотое кольцо 3 px с отступом 2 px: лежит снаружи элемента, поэтому читается и на золотой кнопке.
- **Контрасты заливок и границ подтянуты:** белый текст на синей кнопке был 3.97:1 → фон `#2f63d6`, 5.42:1; зелёная кнопка 3.14:1 → тёмный текст на `#3fd08a`, 9.23:1; граница карточки 2.03:1 → `#4576cc`, 3.09:1 (карточка отличается от фона всего на 1.09:1, её видно только по границе).
- **Иерархия кнопок выровнена:** золотом светится то, что делают следующим. Во время упражнения это «Подход выполнен» (его жмут по 3 раза), а «Следующее упражнение» становится главным, когда подходы отмечены. На вопросе «Ещё хочешь?» золото у «Да, хочу ещё», «Нет, закончить» — спокойной кнопкой.
- Цифры счётчиков переведены на `tabular-nums` — не прыгают по ширине.
- Проверено на выложенной версии (375×812): золотая кнопка, кольцо фокуса по Tab, панель отдыха, подмена главной кнопки по состоянию подходов.

### Первая проба на живом iPhone (Женя) и три исправления
Наблюдения целиком — `USABILITY_OBSERVATIONS.md`. Работали без замечаний: офлайн-видео в авиарежиме, звук таймера, таймер 30 секунд нашла сама, «Убрать из избранного» + «Отменить».

- **Выбор упражнений оставался от прошлой тренировки.** Черновик задумывался как защита от потери выбора при выходе из мастера, но после старта тренировки выбор уже «израсходован». → `startCustom()` сбрасывает черновик сразу после начала; повторить прежний набор можно из Истории («Повторить эту тренировку»). Правило стандарта §4 не нарушено: обратное действие сохранилось, но живёт там, где ему место.
- **«Добавить в Календарь» показывало белый экран**, и приложение приходилось перезапускать. Переход по ссылке на `.ics` уводил из PWA, запущенной с экрана «Домой», — а вернуться оттуда нечем (антипаттерн §16). → Файл напоминания собирается в самом приложении (`icsText()` в `calendar.ts`) и отдаётся через системное «Поделиться» (`navigator.share` с файлом), если оно есть; иначе — обычное сохранение файла. Приложение при этом не покидает экран. Плюс ручная подсказка словами: «понедельник, среда, пятница в 19:00». В nginx `.ics` теперь отдаётся как вложение, а не открывается во вкладке.
- **«Пропустить» не помещалось на узком экране.** Таймер, «+15 с» и «Пропустить» стояли в одну строку. → Панель отдыха перестроена в два ряда: крупные цифры и полоса сверху, две кнопки во всю ширину снизу. Цель нажатия выросла до 167×52 pt (норма — 44×44).
- Тестов в `web-app` стало 13: сброс черновика после старта и содержимое файла напоминания (повтор, время, будильник) проверяются автоматически.
- Проверено на выложенной версии в окне 375×812: черновик пуст сразу после старта, кнопка не обрезана, нажатие на «Добавить в Календарь» не меняет адрес и не гасит экран.

### Синхронизация контента заработала
- Google Cloud: проект `trenazher-509109`, ключ `trenazher-server` — только Sheets API + Drive API, только с IP сервера.
- **Проблема: ключ сохранился трижды подряд** (при скрытом вводе вставили три раза). → `trenazher-set-key` теперь требует ровно 39 символов, начиная с `AIza`, называет длину вставленного и даёт три попытки.
- **Проблема: Google отклонял сервер по IP.** Сервер ходит в Google по IPv6 (`2a01:4f9:c015:a064::1`), а в ключе был только IPv4. → В ограничения ключа добавлен IPv6.
- **Проблема: папка была открыта только приглашённым** («Доступ ограничен»). Ключ ходит без аккаунта, поэтому получал 403. → Женя включила «Все, у кого есть ссылка → Читатель».
- Первая синхронизация: 40 упражнений, 39 файлов, сопоставленных автоматически (фото у 15 упражнений). Видео сжаты в 5–35 раз, длительность сохранена (проверено ffprobe).
- **Проблема: Google временно блокирует массовое скачивание** — отвечает 403 со страницей «Sorry…» после ~37 файлов подряд. → Пауза 3 с между скачиваниями; при такой блокировке синхронизация останавливается и докачивает остальное в следующий запуск. Недокачанный файл удаляется.

### Выкладка на сервер
- `https://trenazher-135-181-197-13.nip.io` — бесплатный HTTPS-адрес по схеме planner/portugesh. Голый `http://135.181.197.13` не подходит: без HTTPS iPhone не даёт офлайн и Wake Lock.
- Сервер: ffmpeg и python3-pil; системный пользователь `trenazher`; nginx-сайт `trenazher` (проверка `nginx -t` перед перезагрузкой); сертификат Let's Encrypt через certbot; `trenazher-sync.timer` раз в 10 минут с `nice 19`.
- Напоминания — `/reminder.ics` в nginx: повторяющееся событие для Календаря iPhone по параметрам из приложения, параметры проверяются регулярными выражениями.
- Проверено: HTTPS, редирект, service worker активен, календарь, отказ на неверные параметры; соседние сайты сервера отвечают 200.

### Веб-версия (PWA) вместо нативной
- **Решение:** у команды нет физического доступа к iPhone Андрея, а платный Apple Developer ($99/год) не берём. Нативное приложение тогда не установить удалённо: бесплатная подпись требует подключать телефон к Mac раз в 7 дней. Единственный бесплатный путь без доступа к устройству — веб-приложение. Нативная версия заморожена, код сохранён.
- `content-sync/` — порт логики разбора и сопоставления со Swift на Python: те же правила, те же ID упражнений, те же тексты замечаний. 11 тестов, включая сквозной прогон фото и видео через ffmpeg.
- `web-app/` — React + TypeScript + Vite без UI-библиотек, те же экраны, что в нативной версии. Данные Андрея — в `localStorage` устройства после каждого действия; резервная копия файлом с объединением без дублей. Service worker: оболочка в кэше, манифест «сначала сеть», фото докачиваются все, видео — по кнопке «Скачать для офлайна» с поддержкой перемотки.
- Найдено при проверке в браузере и исправлено:
  - **пустой экран при переходе к следующему упражнению** — `useEffect` с выражением вместо блока возвращал значение, React вызывал его как функцию очистки. Эффекты переписаны блоками, добавлен экран ошибки «данные сохранены, перезапустить»;
  - текст просвечивал сквозь липкие панели — фон сделан непрозрачным.
- Стандарт юзабилити обновлён до v1.5: канал установки выбирается до платформы; пустой экран после сбоя — антипаттерн.

### Без платного Apple Developer
- **Решение:** синхронизация iPhone ↔ iPad через iCloud отложена. CloudKit и iCloud KVS выключены конфигурацией, код остался; настройки хранятся локально. Тексты «появится и на iPad» стали условными, переключатель «напоминать на этом устройстве» скрыт.
- `ios-app/TrenazherKit/run-tests.sh`: без Xcode тесты идут на SDK 26.5 с явным путём к плагину Swift Testing. В SDK 27 из Command Line Tools `@State` стал макросом без плагина, а `swift test` без явного пути не находит `TestingMacros`.

## 2026-09-18

### Нативная версия (SwiftUI, iOS 14+)
- Пакет `TrenazherKit` (логика + все экраны) и тонкий таргет приложения; проект Xcode генерируется XcodeGen (`project.yml`). Пакет собирается и под macOS 11 — так компилятор ловит API новее iOS 14 без Xcode.
- Контент: разбор таблицы по заголовкам (часть тела и группа мышц — только в первой строке раздела), строгое сопоставление файлов, клиент Sheets/Drive по API-ключу, кэш JSON + медиа с версией в имени, синхронизация с докачкой после обрыва.
- Данные: избранное и история — Core Data + CloudKit, настройки — iCloud KVS, локальные уведомления.
- Тренировка: чистая модель сессии, у каждого шага есть обратный; сохранение после каждого действия; таймер от времени окончания.
- 32 теста на реальной выгрузке таблицы. Утилиты `content-report` (отчёт по контенту) и `screen-previews` (рендер экранов в PNG без Xcode).
